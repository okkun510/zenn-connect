# Web 画面をつくるときの苦悩

web 画面（UI）ってどうやってつくっているか？と考えた時に、ページ１枚を一気に作るんかな？と思われる方も多いでしょう。
もちろんそういう作り方もあるのですが、それだと困ることがあるのです。

例えば

- 同じボタンのデザインを使う時に、ページ毎にボタンのデザインを記述しないといけない
- 同じように書いていたと思ったら書き方が違っていてデザインがおかしくなった
- 長いページだと記述量が多くなってしんどい

といったことが発生してしまうんですよね。

このしんどさって、全て言いかえると

> 同じデザインは使いまわしたい

に尽きると思うんですよね。
その夢を叶えるのが「Atomic Design」なんです！

# Atomic Design ってなあに？

デザインってついていますが、デザインの話ではなく、画面をどうやって組み立てていくか、という設計手法です。

Atomic Design は、Brad Frost（ブラッド・フロスト）さんという方が考えた設計手法です。

この人はこう考えました。

> 「私たちはページをデザインしているんじゃない。パーツの組み合わせをデザインしているんだ」

つまりデザインってついていますが、デザインの話ではなく、画面をどうやって組み立てていくか、という設計手法なんですねー

そしてこの考え方に名前をつけるとき、化学からヒントを得ました。

化学の世界では、すべての物質は「原子（Atom）」からできています。
原子が集まると「分子（Molecule）」になり、
分子が集まると「有機体（Organism）」になり...
という感じで、小さいものが組み合わさって複雑なものができていきます。

「画面も同じやん！」ということで、この名前になりました。

つまり、web ページを一気に作るやり方ではなく、ページを構成する要素をパーツに見立てて組み上げていってしまおう！ってことなんですねー

パーツは５つに分かれていて、それぞれに名前がついています

1. atom（アトム・原子って意味）
2. molecule（モレキュール・分子って意味）
3. organism（オーガニズム・生物とか有機体とかって意味）
4. template（テンプレート）
5. page（ページ）

このままではなんのことかさっぱりわからんので、料理に喩えていきたいと思います。

みなさん料理ってされますか？（私は嫁に軽く禁じられている、汚すからとか言って・・・）

料理の工程って、

1. 食材を準備する → **atom**
2. 食材を下処理する（切ったりして使いやすい状態にする） → **molecule**
3. 調理する → **organism**
4. 盛り付けしたり配置したりする → **template**
5. 完成 → **page**

って流れじゃないですか？だいたいね。
それと似たような感じで作っていくのが Atomic Design です

それぞれの工程を見ていきますね

## atom について

atom とは、web 画面（UI）における一番小さいパーツの単位です。
例えば、

- ボタン
- 入力欄
- ラベル

なんかがこれに相当します。

料理に例えると食材です。にんじんとか玉ねぎとかお肉とか醤油とか。

atom はよく「UI を構成する最小単位のパーツ」と言われたりします。
料理に例えると「料理を構成する最小単位のパーツ」になります。食材がそれですよね。
食材たちは自分が何に使われるかは知りません。
「俺はカレーになるために生まれた玉ねぎだ！！！」なんて思ってる玉ねぎはいないように、
ボタンや入力欄も自分たちがどんな画面に使われるかは知りません。彼らは何にでもなれる存在です。

atom を下処理したり、組み合わせてできるのが次の molecule です

## molecule について

molecule とは、いくつかの atom（または molecule）を組み合わせて構成されているパーツの単位です。
例えばさっきの「ボタン」「入力欄」「ラベル」を組み合わせたら入力フォームになります。

料理に例えると、にんじんや玉ねぎを切って混ぜ合わせた状態でしょうか。お肉だったら切ったりしますかね。

molecule は atom を組み合わせてさらに使いやすくした状態です。
ある程度形は決まってきますが、まだ何にでも使えます。

にんじんや玉ねぎを切って混ぜ合わせたら、ある程度食べ方は決まってきますが、まだ肉じゃがになる余地や、カレーになる余地を秘めています。

先述した入力フォームも画面のパーツとしていろいろな使い方ができます。
名前入力欄だったり、アドレス入力欄だったり。

つまり、molecule とは、
「組み合わせた結果、ある程度の形は決まってくるが、まだまだいろんなところで使えるパーツ」
です。

それらをさらに組み合わせていくとどうなるでしょうか。
それが次の organism です

## organism について

organism とは特定の画面についての知識を持つパーツです。
organism として作られたパーツは、他の画面では利用することはできません。
それ単体で Web サイト内で存在できるもので、何をするものかが一目でわかります。
例えば、ヘッダー（画面上部のメニューバー）や、さっきの入力フォームを組み合わせて、お問い合わせフォームや、申し込みフォームなど作ると、それが organism になります。

料理に例えると、完成した一品です。
先ほどの玉ねぎやにんじんを切って混ぜ合わせたものに、お肉と、カレールウを入れたらどうなるでしょうか？
これはもうカレーになるしかないですよね。
カレーにしてしまったものは、他の料理には使うことはできません。ライスにかけようがうどんを入れようがカレーはカレーです。
また、カレーはそれだけで料理として存在できるものであり、どんな料理かが一目でわかります。

画面で言うと、ヘッダーはヘッダーとしてしか使えませんし、お問い合わせフォームは他の用途には使えません。
でも、それ単体で「あ、これはヘッダーやな」「これは問い合わせフォームやな」とわかりますよね。

さあ、ここまでで「料理」は完成しました。
でも定食屋さんで出すには、まだ足りないものがあります。

お盆に乗せて、どこに何を置くか決めないといけません。
それが次の template です。

## template について

template とは、レイアウト（配置）を決めるためのパーツです。
「ここにヘッダー、ここにメインコンテンツ、ここにサイドバー」という骨組みだけを定義します。

料理で言うと、お盆や定食のお皿の配置です。
「ここにご飯、ここに汁物、ここにメイン、ここに小鉢」という位置だけが決まっている状態。
まだ実際の料理は乗っていません。

template は「枠」だけを用意して、中身は後から入れる、というイメージです。

さて、いよいよ最後です。

## page について

page とは、template に実際のデータを入れた完成品です。
ユーザーが実際に目にする画面そのものです。

料理で言うと、お盆に実際の料理を乗せた「完成した定食」です。
お客さんに「お待たせしました！」と出せる状態ですね。

template が「ここにカレーを置く予定」という枠だったのに対して、
page は「実際にカレーが盛られている」状態です。

書いててお腹空いてきました

## まとめ

Atomic Design とは、画面を小さいパーツから組み立てていく設計手法です。

| 階層     | UI で言うと                        | 料理で言うと               |
| -------- | ---------------------------------- | -------------------------- |
| atom     | ボタン、入力欄、ラベルなど         | 食材                       |
| molecule | 入力フォームなど                   | 下処理した具材             |
| organism | ヘッダー、お問い合わせフォームなど | 完成した一品（カレーとか） |
| template | ページのレイアウト                 | お盆の配置                 |
| page     | 完成した画面                       | 完成した定食               |

いかがでしたか？
「なんとなくこんな感じで画面作ってるんやな〜」と思っていただけたら嬉しいです。

ただ、Atomic Design はあくまで「考え方」であって、実際にどう運用するかはチーム次第だったりします。
「自分のチームでは実際どうやって Atomic Design を使ってるの？」という話もできたらいいなと思っているので
もし次があれば見ていただけたら幸いです。
