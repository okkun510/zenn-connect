# 前編のおさらい

前編の内容を簡単におさらいすると、

- Atomic Design は、画面を小さいパーツから組み立てていく設計手法
- パーツは 5 つの階層に分かれている

| 階層     | UI で言うと                        | 料理で言うと               |
| -------- | ---------------------------------- | -------------------------- |
| atom     | ボタン、入力欄、ラベルなど         | 食材                       |
| molecule | 入力フォームなど                   | 下処理した具材             |
| organism | ヘッダー、お問い合わせフォームなど | 完成した一品（カレーとか） |
| template | ページのレイアウト                 | お盆の配置                 |
| page     | 完成した画面                       | 完成した定食               |

という内容でした。

今回は「実際どうやって Atomic Design を使ってるの？」という実践編をお話しします。

# UI ライブラリって知ってますか？

いきなり実践の話に入る前に、1 つ説明させてください。

前編で、atom にはボタンや入力欄があると説明しました。
でも、これを 1 から自分で作るのってめちゃくちゃ大変なんですよね。

例えばボタン 1 つとっても、

- 見た目（色、形、大きさ）
- 押したときの動き
- マウスを乗せたときの変化
- 押せない状態のときの見た目

などなど、考えることがたくさんあります。
これを全部自分で作るのは正直しんどい...。

そこで登場するのが「UI ライブラリ」です。
**ボタンや入力欄などのパーツをまとめたコレクション**のことで、これを使えば自分で 1 から作らなくてもいいわけです。

料理で言うと、**食材キット**みたいなものでしょうか。
「カレーセット」を買ったら、にんじんや玉ねぎやルウが全部入ってる、みたいな。

## 私たちのチームでは shadcn/ui を使っています

UI ライブラリにもいろいろ種類があるのですが、私たちのチームでは「shadcn/ui」というものを使っています。

https://ui.shadcn.com/

shadcn/ui の特徴は「コピペして自分のプロジェクトに取り込む」スタイルであること。
食材キットを買ったけど、自分の台所に持ってきて、好きにアレンジできる、という感じです。

私たちのチームでは、この shadcn/ui をベースにしながら、Atomic Design の考え方で整理しています。

# 私たちのチームのディレクトリ構造

お待たせしました！本題です。
実際のフォルダ構成を見てみましょう。

```
ui/
├── primitives/      ← shadcn/uiのベースパーツ
├── components/
│   ├── atoms/       ← 最小単位のパーツ
│   ├── molecules/   ← atomsを組み合わせたもの
│   └── organisms/   ← 特定の機能を持つまとまり
└── utils/           ← 便利ツール
```

おや？前編の 5 階層と違いますね。
template と page がありません。

## なぜ 5 階層じゃないの？

Atomic Design はあくまで「考え方」なので、そのまま使う必要はないんです。
チームやプロジェクトに合わせてアレンジするのが普通です。

私たちのチームでは、template と page は「UI パーツ」というより「画面そのもの」なので、別の場所で管理しています。
ここでは「パーツ」に集中しているというわけです。

## primitives ってなに？

先ほど説明した shadcn/ui のパーツをそのまま置いている場所です。

料理で言うと、「食材キットをそのまま冷蔵庫に入れた」状態。
まだ手を加えていない、届いたままの食材です。

## atoms、molecules、organisms の関係

ここからが Atomic Design の本領発揮です！

### atoms（最小単位）

primitives をラップして、私たちのチーム用に使いやすくしたものです。
ボタン、入力欄、ラベルなど。

ここがポイントなんですが、shadcn/ui があるおかげで、atoms を 1 から作る必要がありません。
primitives にある「届いたままの食材」を、ちょっとだけ手を加えて使いやすくするだけで OK。

shadcn/ui のボタンには「色を変える」「大きさを変える」「アイコンを付ける」といった機能が最初から用意されています。
私たちのチームの atoms はそれをそのまま引き継いでいるので、1 から機能を作る必要がありません。

料理で言うと、食材キットの野菜を袋から出して洗った状態、みたいな感じです。
「すでにカット済み」「下味付き」みたいなオプションもそのまま使えます。

```tsx
// atoms/Button
import { Button as PrimitiveButton } from "../../../primitives/button";
import { ComponentProps } from "react";

export type Props = ComponentProps<typeof PrimitiveButton>;

export const Button = (props: Props) => {
  return <PrimitiveButton {...props} />;
};
```

やってることはシンプルで、「primitives のボタンをそのまま使えるようにしてるだけ」です。

ポイントは `{...props}` の部分。これは「外から渡された props を全部そのまま渡す」という意味です。

つまり、primitives のボタンが持っている機能（色を変える、大きさを変える、アイコンを付けるなど）が、そのまま atoms のボタンでも使えます。

### molecules（組み合わせ）

atoms を組み合わせて作ったパーツです。
入力フォーム、ダイアログ、ドロップダウンメニューなど。

料理で言うと、下処理した具材。まだいろんな料理に使える状態。

molecules にはいくつかのパターンがあります。

- **中身を外から渡すパターン**：ダイアログなど。タイトルや中身を渡すだけで、面倒な組み立ては全部やってくれる
- **データを渡すといい感じにしてくれるパターン**：セレクトボックスなど。選択肢の配列を渡すだけ
- **計算もやってくれるパターン**：プログレスバーなど。「今 3 件中 2 件終わった」と渡すと、パーセンテージの計算まで自動でやってくれる

#### パターン 1：中身を外から渡す（Dialog）

```tsx
// molecules/Dialog
export const Dialog = ({
  open,
  onOpenChange,
  title,
  description,
  children,
  footer,
  showCloseButton = true,
  className,
}: Props) => {
  return (
    <AtomDialog open={open} onOpenChange={onOpenChange}>
      <DialogContent showCloseButton={showCloseButton} className={className}>
        <DialogHeader>
          <DialogTitle>{title}</DialogTitle>
          {description && <DialogDescription>{description}</DialogDescription>}
        </DialogHeader>

        {children}

        {footer && <DialogFooter>{footer}</DialogFooter>}
      </DialogContent>
    </AtomDialog>
  );
};
```

atoms の「ダイアログ本体」「ヘッダー」「タイトル」「フッター」を組み合わせて、使いやすい「ダイアログセット」にしています。使うときは props でタイトルや中身を渡すだけ。

#### パターン 2：データを渡すといい感じにしてくれる（Select）

```tsx
// molecules/Select
export const Select = ({
  value,
  onValueChange,
  placeholder,
  options,
  disabled,
  className,
}: Props) => {
  return (
    <SelectAtom value={value} onValueChange={onValueChange}>
      <SelectTrigger className={className} disabled={disabled}>
        <SelectValue placeholder={placeholder} />
      </SelectTrigger>
      <SelectContent>
        {options.map((option) => (
          <SelectItem key={option.value} value={option.value}>
            {option.label}
          </SelectItem>
        ))}
      </SelectContent>
    </SelectAtom>
  );
};
```

選択肢のデータ（options）を渡すと、中でいい感じに展開してくれます。

#### パターン 3：計算もやってくれる（Progress）

```tsx
// molecules/Progress
export const Progress = ({ currentValue, maxValue, className }: Props) => {
  const calculatedValue = maxValue > 0 ? (currentValue / maxValue) * 100 : 0;

  return <AtomProgress value={calculatedValue} className={className} />;
};
```

「現在値」と「最大値」を渡すと、パーセンテージの計算まで自動でやってくれます。

### organisms（特定の機能）

molecules や atoms を組み合わせて、特定の目的を持たせたパーツです。
お問い合わせフォーム、ヘッダー、ドラッグ&ドロップで並び替えできるリストなど。

料理で言うと、完成した一品。もうカレーはカレー、味噌汁は味噌汁。
他の料理に流用はできないけど、「この一品」としては完成している状態です。

organisms の特徴は、**特定の目的**を持っていること。
molecules は「いろんな場面で使える汎用パーツ」でしたが、organisms は「この場面専用」のパーツです。

```tsx
// organisms/AppLayout
import { Button } from "../../atoms/Button";
import { Icon } from "../../atoms/Icon";
import { Separator } from "../../atoms/Separator";
import { Sheet } from "../../molecules/Sheet";
import { AlertDialog } from "../../molecules/AlertDialog";
import { Sidebar } from "../../molecules/Sidebar";
import { DropdownMenu } from "../../molecules/DropdownMenu";
import { Avatar } from "../../molecules/Avatar";

export const AppLayout = ({ header, sidebar, children }: Props) => {
  return (
    <>
      <header>
        <a href={header.logo.href}>
          <img src={header.logo.src} alt="MyApp" />
        </a>
        <Sheet trigger={<Button><Icon name="userIcon" /></Button>}>
          {/* ユーザーメニュー */}
        </Sheet>
      </header>
      <div>
        <Sidebar
          content={<SidebarMenu items={sidebar.menuItems} />}
          footer={<DropdownMenu ... />}
        />
        <main>{children}</main>
      </div>
    </>
  );
};
```

import の部分を見ると、atoms と molecules をたくさん組み合わせているのがわかります。

- atoms：`Button`、`Icon`、`Separator`など
- molecules：`Sheet`、`AlertDialog`、`Sidebar`、`DropdownMenu`、`Avatar`など

これらを組み合わせて「アプリのレイアウト」という特定の目的を持ったパーツにしています。このコンポーネントは汎用的ではなく、このアプリ専用です。

## template と page はどうしてるの？

前編で Atomic Design は 5 階層あると説明しましたが、私たちのチームでは template と page を作っていません。

じゃあどうしてるの？というと、**Next.js の App Router に任せています**。

Next.js というのは、私たちのチームが使っている Web アプリケーションのフレームワーク（開発の土台となるツール）です。
この Next.js には「レイアウト」と「ページ」という仕組みが最初から用意されていて、これが Atomic Design の template と page の役割を果たしてくれます。

```
app/
├── layout.tsx      ← これがtemplate的な役割
├── page.tsx        ← これがpage的な役割
├── companies/
│   ├── layout.tsx  ← 会社一覧のレイアウト
│   └── page.tsx    ← 会社一覧のページ
└── ...
```

料理で言うと、「お盆の配置」と「完成した定食」の部分は、Next.js という厨房設備がやってくれる、みたいな感じです。

わざわざ自分たちで template や page のフォルダを作らなくても、Next.js のルーティング機能がその役割を担ってくれているので、私たちのチームでは UI パーツ（primitives〜organisms）に集中しています。

実際のページでは、organisms を組み合わせて使います。

```tsx
// app/companies/page.tsx
import { AppLayout } from "@/components/organisms/AppLayout";
import { CompanyList } from "@/components/organisms/CompanyList";

const CompaniesPage = () => {
  return (
    <AppLayout header={...} sidebar={...}>
      <CompanyList companies={companies} />
    </AppLayout>
  );
};
```

`AppLayout`という organisms の中に、`CompanyList`という organisms を入れる。
こうやって organisms 同士を組み合わせて、1 つの画面を作っていきます。

# まとめ

前編・後編にわたって Atomic Design についてお話ししました。

**前編**では、Atomic Design の基本的な考え方を紹介しました。

- 画面を小さいパーツから組み立てていく設計手法
- 5 つの階層（atom → molecule → organism → template → page）

**後編（この記事）**では、実際の運用方法を紹介しました。

- shadcn/ui をベースにして、primitives → atoms → molecules → organisms の 4 階層で管理
- template と page は Next.js の App Router に任せる
- 各階層の役割と、実際のコード例

Atomic Design は「正解」があるものではなく、チームやプロジェクトに合わせてアレンジするものです。
この記事のやり方が参考になれば嬉しいです！
